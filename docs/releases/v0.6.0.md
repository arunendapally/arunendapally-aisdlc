# v0.6.0: specs that say more, work across repos, and evals that stay in their sandbox

- PRDs name their non-functional requirements; plans answer error handling and data and tenancy.
- Tasks say what they wait for; work across repos declares its systems under change, and `sdlc packets` splits it per repo.
- Big capabilities keep a slice record that `sdlc status` shows.
- `start` builds on what is already in the folder, asks less and logs assumptions; a second repo, like a high-risk path, moves work to the full lane.
- The light lane reads its outcome after 7 days; the PRD names its objective.
- Approval signals per gate in `sdlc metrics` and the retro, never per person.
- Agent evals run with no MCP servers or user settings.

Update: `claude plugin marketplace update arunendapally-aisdlc`, then `claude plugin update ai-sdlc@arunendapally-aisdlc`, then a new session. Features already in flight: a Build with tasks that lack `depends-on: [..]`, and a light-lane Release without outcome lines, will be refused until they add them.
