# v0.8.0: a person decides at the intent and the PR, and nowhere else

- **Every lane ends at Verify, at a raised PR** (ADR-0008). Merge, deploy and release are your org's. Define and Design pass on their checks on the feature's own branch (ADR-0007), so a person answers the intent and reviews the PR. Stages have names: Define, Design, Build, Verify. The unused Release check and the `release.md` template are gone. PRs #51, #54, #56, #61, #63, #64.
- **The gates-and-names capability:** a definition of done per stage, plan as a roadmap with tickets per repo, one architecture overview with a decision log per capability, test lock, change request or amend after Build starts, and `sdlc trace` for requirements both ways. A feature left at stage 6 completes on its next request. PRs #59, #60.
- **Less toil around the checks** (issue #62). Set the gate once with `sdlc gate-command <command>` and every worktree uses it. Hook logs live in the git common dir, so worktrees stay clean. Denials name their guard and what to do instead; `bashAllow` lets a person allow commands. `fixed: HEAD`, gate reuse at Verify, named open nits, and no subagent for changes under 30 lines. PR #65.
- **New commands:** `sdlc worktree <lane> <slug>`, `sdlc ship <slug>`, `sdlc pr <slug>`, `sdlc cleanup`, `sdlc changelog` (fragments in `changelog.d/`), `sdlc bug <slug> --issue <n>`. PR #66.
- **Runs need a person only at the intent and the PR.** A command that only reads is no longer refused for naming a person's command. `sdlc init-repo` sets the gate and proof commands from what the repo holds. `sdlc next <capability>` names the slice to work next, and `/ai-sdlc:run` takes work from the intent to the raised PR. A person's answer is recorded in the worktree where its feature lives. New guards refuse an inline program that touches a proved test, code on the protected branch before work starts, and a recursive delete outside the repo. **Fixed:** `sdlc gate` no longer loses a decision recorded while it ran. PR #67.

Update: `claude plugin marketplace update arunendapally-aisdlc`, then `claude plugin update ai-sdlc@arunendapally-aisdlc`, then start a new session.

Features already in flight, after updating:

- A feature left at stage 6 by an older plugin completes on its next `sdlc request`.
