The one-developer AI SDLC skill becomes a Claude Code plugin for teams of humans and agents. Agents do the work; a named human decides at every gate; every rule that matters is a check, not a sentence in a prompt.

## Install

```bash
claude plugin marketplace add arunendapally/arunendapally-aisdlc
```

```bash
claude plugin install ai-sdlc@arunendapally-aisdlc
```

Then follow [docs/getting-started.md](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/getting-started.md).

## Highlights

- **Every kind of work has a route.** `/ai-sdlc:start` triages a request into a lane:

  | Lane | Human gates |
  |---|---|
  | full | 6 |
  | light | 5 |
  | bug | 1 |
  | task | 1 |
  | hotfix (declared by a human) | 2 |

  Kinds for greenfield, brownfield, performance, data and API work stack on top and add what each needs.
- **Requirements that ask, not assume.**
  - A PRD that records the questions asked and marks every assumption.
  - System facts pinned to `file:line` that go stale when the code changes.
  - Gherkin acceptance criteria checked for coverage of every requirement.
- **Designs that survive questioning.**
  - ADRs with two options and a named downside.
  - A design review board of at least three disciplines that must accept each decision.
  - ER diagrams for data work, and OpenAPI contracts with breaking changes declared and a Swagger viewer.
- **Tests at the right level, with clean data.**
  - A test matrix traces every criterion to a unit, subsystem, API or E2E test.
  - An SDET agent and scaffolds cover Vitest, Testcontainers, Postman with Newman, and Playwright.
  - Checks catch flaky tests and leaked test data.
- **Code review you can measure.**
  - A review packet shows where the risk is.
  - Expert lenses include a Ponytail-style simplicity lens.
  - A findings ledger the gate enforces.
  - The pre-review's catch rate, measured against what humans find.
- **Autonomy is earned.** Clean approvals let a human promote a gate to pass on checks alone. A rejection, an escaped bug or an error-budget freeze takes it back.
- **It improves itself.** `sdlc retro` turns what was recorded into proposed plugin changes, each proven by golden and agent evals before a human merges it.
- **Autopilot mod (optional):** a gate board, stage rules and knowledge in every turn, and a capped test-and-fix loop.

## Proven on itself

The last part of this release was built through the plugin:
- The design review board sent ADR-0001 back with 11 questions, then accepted it after code changes.
- The agent pre-review found 12 defects in the new gates; all are fixed, each with a regression test.
- 66 tests and 12 golden evals pass.
- 8 of 9 agent evals pass. These include five seeded-bug review evals: SQL injection, a missing ownership check, an off-by-one, a test that asserts nothing, and over-engineering.

## Known limitations

- The hooks have been tested by running their scripts, not yet inside live sessions on a real team feature.
- The repo-kit workflows and ruleset are templates that have not yet run in a product repo.
- The OpenAPI check is structural; run Redocly or Spectral in CI for full validation.
- The test scaffolds assume TypeScript, Vitest, Postgres, Newman and Playwright.
