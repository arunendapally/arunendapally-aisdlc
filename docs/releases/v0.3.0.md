# v0.3.0: simpler, and gates that catch real failures

<!-- GitHub release notes. Publish after the release PR merges:
     gh release create v0.3.0 --target main --title "v0.3.0: simpler, and gates that catch real failures" --notes-file docs/releases/v0.3.0.md -->

A feature now waits on a human three times (the spec, the merge, the release) and a bug once. The gates were rebuilt around three real failures, review now converges, and an approval covers exactly what was checked.

## Install or update

New install:

```bash
claude plugin marketplace add arunendapally/arunendapally-aisdlc
```

```bash
claude plugin install ai-sdlc@arunendapally-aisdlc
```

Updating from v0.2.0:

```bash
claude plugin marketplace update arunendapally-aisdlc
```

```bash
claude plugin update ai-sdlc@arunendapally-aisdlc
```

Then start a new Claude Code session and follow [docs/getting-started.md](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/getting-started.md).

## Highlights

- **A simple default path ([ADR-0003](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/adr/0003-simple-default-path.md)).**
  - Features start in the light lane: one spec gate, Build passes on checks, and an approval moves the feature on by itself.
  - Templates and checks are much shorter: the PRD went from 14 required sections to 9, the PR body from 10 to 4. Agents went from 21 to 14, commands from 18 to 14.
  - Everything beyond the safety core is optional until the risk calls for it.
- **Gates that catch the real failures ([ADR-0004](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/adr/0004-gates-that-catch-real-failures.md)).**
  - A denial is a final answer. Two in a session hand back to a human; rephrasing counts too.
  - Large files must be read in slices, after the code that governs them.
  - Release refuses unless the reviewed change is on `origin/main` and the running build (`Live: <sha>`) contains it.
  - `npm run eval` prints CAUGHT or NOT CAUGHT for each known failure.
- **Review that converges ([ADR-0005](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/adr/0005-review-converges-and-risk-is-set-by-the-change.md)).**
  - Review rounds are capped at three; re-review covers only the new diff.
  - An approval lapses if the content changes before it is given.
  - Risk is set by the files the change touches, and a pre-review can only raise it.
  - Every merge needs a person. `sdlc close` retires work that will not ship.
- **The loop spine ([ADR-0002](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/adr/0002-loop-spine.md)).** `sdlc proof` shows a feature's tests pass on the branch and fail on the old code. Outcome follow-ups, spikes and a triggered retro.
- **The council as a dynamic workflow.** `/ai-sdlc:council` runs experts in parallel, has a sceptic check each review against the code, and writes a proposal for a human to accept. On its first real decision it caught a recommendation that would have loosened a guard.
- **Easier to start.** The README and getting-started guide lead with three steps to a first feature.

The autopilot mod is now 0.2.0: it counts an edit only once the tool succeeded, starts nothing after a denied turn, and no longer restarts itself on green.

## Proven

- 102 tests and 24 golden evals pass. The evals catch all four recorded failures (F1 to F4).
- This release was built with the plugin installed: its guards ran on every agent command, which is how the guard false positives below were found.

## Known limitations

- The agent evals (`npm run eval:agents`) were not rerun for this release.
- The Bash guard still refuses some harmless chained commands and lets `git push origin +main` through; the fix is proposed in [docs/decisions/2026-10-23-bash-guard-targets.md](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/decisions/2026-10-23-bash-guard-targets.md). The GitHub ruleset remains the real protection for main.
- No team has yet run a feature end to end in a product repo.
