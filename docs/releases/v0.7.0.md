# v0.7.0: requirements not solutions, templates at every stage, and gates that check what they claim

- **The PRD states needs, never solutions.** A light-lane feature writes its design in `## Approach` in `tasks.md`, and the Plan gate warns when a requirement names a mechanism.
- **Every stage's template is rewritten by a council.** Each shows a filled example and follows one running story, and ten bugs in the old ones are fixed. C4 Level 1 is in the architecture overview, Levels 2 and 3 in the plan.
- **`db-design.md` is the data contract the DBA owns.** Its sections are due stage by stage; the light lane is now asked for a migration plan.
- **What the checks no longer pass:**
  - criteria the proof never ran;
  - a value read from the next line;
  - a failed probe;
  - a planned rollback date;
  - a gate command that cannot start, which used to read as a new repo.
- **The gate records its runtime,** and warns when it changes.
- **Criteria with no test file.** `@release` criteria are proved by a release probe, and `@manual` ones by a dated hand check; `proofSkipLevels` leaves a browser suite to its own run.
- **`sdlc import-speckit`** starts Plan from a GitHub Spec Kit spec.
- **`docs/other-agents.md`** says what holds without Claude Code.

Update with `claude plugin marketplace update arunendapally-aisdlc`, then `claude plugin update ai-sdlc@arunendapally-aisdlc`, then start a new session.

Features already in flight, after updating:
- Approvals hold, and a data feature keeps its sections where they were.
- A light-lane feature now needs `## Approach` in `tasks.md` at its next Build request.
- A release with a failed probe, or a rollback date in the future, is refused.
