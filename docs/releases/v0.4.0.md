# v0.4.0: your intent first, and a guard that reads what a command does

A feature now starts from what you typed it is for, and every approval shows that back to you. Work the spec no longer covers goes back for approval. The Bash guard stops refusing harmless commands and closes a push bypass.

## Update

```bash
claude plugin marketplace update arunendapally-aisdlc
```

```bash
claude plugin update ai-sdlc@arunendapally-aisdlc
```

Then start a new Claude Code session. New install: see [docs/getting-started.md](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/getting-started.md).

## What changes for you

- **You type the intent.** Before any spec is written:

  ```
  sdlc intent saved-items change: shoppers can come back to items they liked; smallest: a save button and a saved list; drop if: under 5% of shoppers save anything in two weeks
  ```

  Only a person can type it. The PRD waits for it, Plan cannot be requested without it, and the PRD carries your words verbatim.
- **Approvals show you what to judge against:** your intent, the unconfirmed assumptions at Plan, and at Verify the risk tier, the files reviewed and what was not verified.
- **A spec or plan changed after you approved it goes back to you.** At Build, Verify or Release, an edited `prd.md`, `acceptance.feature` or `plan.md` returns the feature to that stage.
- **One feature, one branch.** The gate, proof, review and Build or Verify requests refuse on another feature's branch.

## Safer guards

- **The Bash guard judges each part of a command** on what it targets ([decision](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/decisions/2026-10-23-bash-guard-targets.md)). The chains it wrongly refused between 22 and 26 Oct now pass: reads chained together, a commit message or source file that mentions a guarded path, `gh pr create --base main` after a push. Each of those refusals counted toward `denialCap`.
- **Closed:** `git push origin +main` passed before. Now `+main`, `HEAD:main`, `refs/heads/main`, `--mirror`, `--all` and any `+refspec` are refused.
- **Browser actions from MCP tools ask a person** (navigate, click, type, run script, upload), unless listed in `mcpAllow`. Reading a page does not ask.
- **A paused or held session makes no web calls**: `WebFetch` and `WebSearch` could carry data out in a URL or a query.
- **Fixed:** a repo config could replace `mcpDenyPattern` and remove that guard. MCP patterns can now only be widened.

## Proven

- 118 tests and 28 golden evals pass; the evals catch all four recorded failures (F1 to F4). Every new check has a test that failed before it was built.
- Two council records drove this release: [agile with agents](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/decisions/2026-10-25-agile-with-agents.md) and [fewer, better human asks](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/docs/decisions/2026-10-25-fewer-better-human-asks.md).

## Known limitations

- The intent cannot be changed once Plan is approved; to change direction, close the feature and start again.
- The agent evals (`npm run eval:agents`) were not rerun for this release.
- Proposed but not built: the outcome check in the light lane, a gate queue and optional WIP limit, browser QA, a review by a different model, and the rubber-stamp numbers for the retro.
- No team has yet run a feature end to end in a product repo.

The autopilot mod is unchanged at 0.2.0. Full list: [CHANGELOG.md](https://github.com/arunendapally/arunendapally-aisdlc/blob/main/CHANGELOG.md).
