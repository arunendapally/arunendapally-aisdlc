- **Runs that need a person only at the intent and the PR** (unattended-runs). A shell segment that only reads (`cat`, `grep`, `git log` and the like, with no redirect or substitution) is no longer refused for naming a person's command or the prompt hook, and a refusal of a command made only of reads does not count towards the hold. `sdlc init-repo` sets `gateCommand`, `proofCommand` and `runtimeCommand` from what the repo holds (Node, Python, Go, .NET) in a config it has just created, and proposes them for an existing one; a person sets the proof with `sdlc proof-command <command>`. **Changed on upgrade:** a full or light feature with no `proofCommand` is refused at Verify unless the repo config holds `"proofWaived": "<why>"`. `sdlc next <capability>` names the slice to work next, `sdlc init --capability` carries over the intent a person gave the capability, and `/ai-sdlc:run <feature or capability>` takes work from the intent to the raised PR in one request. The session-start message, the plugin descriptions, the README and getting-started say a person decides at the intent and the PR. A person's answer to a gate, intent or conflict question, clicked or typed in the main checkout, is recorded in the worktree where its feature lives. New refusals: an inline program (`node -e`, `python -c` and the like) that names a proved test, a code edit on the protected branch of a repo that runs the plugin before work is started there (`/ai-sdlc:start`), and a recursive delete outside the repo. Setup no longer copies `.ai-sdlc/autonomy.json`, which no code read. **Fixed:** `sdlc gate` wrote back the feature's record it read when it started, so a decision recorded while the gate ran (an amendment, an approval) was lost; it now keeps what was recorded meanwhile, and records nothing if the feature moved stage. Tests in `tests/unattended-runs.test.mjs`, `tests/unattended-runs-edges.test.mjs` and `tests/read-only-guard.test.mjs`.
